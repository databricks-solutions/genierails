# Compliance evidence report

`make evidence ENV=<env>` writes a versioned JSON artifact and matching Markdown summary of the deployed Unity Catalog tags, masks, grants, and column observation status:

```bash
make evidence ENV=prod
```

Live collection is the default. `OFFLINE=1` writes a config-only report instead: the configured column footprint and tags, without creating a Databricks client. `GENIERAILS_EVIDENCE_INTEGRATION=1`, which older versions needed for live collection, is still accepted and changes nothing.

The SQL warehouse is resolved for you: the env's `sql_warehouse_id`, else one unique `genie_spaces[].sql_warehouse_id`, else the `sql_warehouse_id` output of the applied workspace layer. It stops if none is found or the per-agent values conflict. `WAREHOUSE_ID=<id>` is optional and pins a specific warehouse.

The files are written to the env's state dir, next to the release receipts: `.genierails-state/<env>/evidence/` in the cloud folder (for example `aws/.genierails-state/prod/evidence/`), or `$GENIERAILS_STATE_DIR/<cloud>/<env>/evidence/` on a [deployment machine](deployment-machine.md) that sets it. The command prints both paths. The default folder is git-ignored (the `.gitignore` block that `make setup` writes covers `/.genierails-state/`). A custom `GENIERAILS_STATE_DIR` must be outside every git checkout or git-ignored in each one. Before writing, `make evidence` resolves the evidence folder (symlinks followed) and finds every git work tree around it, nested repos included, by looking for `.git` in the folder and each parent. In each one, `git check-ignore` must confirm both report files are ignored by that repo's own rules (its `.gitignore` files or `.git/info/exclude`; a personal `core.excludesFile` doesn't count) and not tracked. `GIT_*` environment variables such as `GIT_DIR` are ignored for this check. If any check fails, or git can't be run, it exits 2 and writes nothing. The folder is owner-only (`0700`, files `0600`) and outside `envs/`, so `make maintain`, `make release-plan` and `make rehearse` never see it and the checkout stays clean. Each run replaces the previous record, so archive it (for example with the change ticket) if you need to keep it. Older versions wrote to `envs/<env>/generated/evidence/`: if that folder is still there and not committed, archive it and delete it once.

The report holds no credentials: no token, client secret or auth file content is written.

The approval header comes from the env's last release receipt: a `y` typed at a terminal names the git identity, OS user and terminal (its device name, e.g. `ttys004`) it recorded and its time, and what started the make that asked, by command name only (no arguments, paths or environment): `via make <- zsh <- login (make started from a shell)`, or `via make <- python3 <- zsh (make started by python3, not a shell: a script or driver)`; a record written before GenieRails kept that chain says `process chain not recorded`. All of it is self-reported, and the header says so: `self-reported: GenieRails cannot prove a human typed it` (a driver can type `y` on a terminal it controls, even through a shell). A release approved outside GenieRails (the plain `make release MANIFEST=` path) says `external`, and no receipt (or one with no approval) says `unknown`. Only the newest release receipt counts, and only if it passes release-plan's receipt check (this env and cloud, its manifest's sha256) and its approval is still the private record it embedded (same sha256 and fields); otherwise the header says `unverified: <why>` and names no one. `header.approval_record` names the receipt; `round_approvals` counts the final round plus every earlier phase (including an imports-only round), while `earlier_phase_approvals` deliberately excludes the final round. Set `GENIERAILS_EVIDENCE_APPROVED_BY` (and `GENIERAILS_EVIDENCE_APPROVED_AT`) to sign it yourself instead. Each column entry contains its classification scan status/time, detected tags, applied mask, row-filter and ABAC policies, and effective column, table, schema, and catalog grants. The `schema_version` field identifies the artifact contract; JSON is canonical and Markdown is its review-friendly rendering.

Live collection uses the Databricks SDK statement execution API, Unity Catalog `system.information_schema`, and the Unity Catalog policies API. Table-attached masks and row filters come from `information_schema` (legacy envs). ABAC policies, which deterministic governance deploys at catalog level and neither view lists, come from the policies API as the set effective on each governed table (catalog, schema and table level). A policy is attached to a column only when its mapping is fully evaluated and matches: the table's tags (`system.information_schema.table_tags`) satisfy the policy's `when_condition` (none means always), and, for a column mask, the column's tags (for example its `gr_treatment` value) satisfy the match condition whose alias is the mask's `on_column`; a row filter covers every column of its table. Conditions must be an exact OR of `hasTagValue`/`hasTag` checks. `applied_policies` then names the policy and `applied_abac_policies` gives its function, conditions, `to_principals` and `except_principals`. A column covered by both kinds shows both. A policy whose type, `when_condition`, `on_column` binding or match condition can't be evaluated exactly is never shown as protection: it is listed under `abac_policies_not_evaluated` (table, policy, reason), `abac_policy_listing.status` is `incomplete`, and the Markdown carries a warning table. If the policies or the table tags can't be read, `make evidence` exits 2 and writes nothing, instead of reporting a governed column as unprotected. If the env's `auth.auto.tfvars` is missing or incomplete it also exits 2 and writes nothing; `OFFLINE=1` needs no credentials. Run directly, `evidence_report.py` stays offline unless `GENIERAILS_EVIDENCE_INTEGRATION` is truthy (`make evidence` sets it), keeping unit tests credential-free.
